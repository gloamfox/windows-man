WSL的“自动启动”通常涉及两个层面：一是让WSL本身随Windows系统启动而运行；二是让WSL内部的命令或服务（如Docker、Nginx）在WSL启动时自动执行。

## 🚀 方案一：让 WSL 随 Windows 自动启动
这需要借助Windows的机制来“拉起”WSL进程。

### 使用任务计划程序（最推荐，功能最全）
这是最灵活、最可靠的方式，可以设置开机或登录时触发，并支持后台静默运行。

你可以以管理员身份打开 PowerShell，然后执行下面这段脚本。它会创建一个名为 WSL-AutoStart 的计划任务，在你登录Windows时自动启动WSL并保持其后台运行，防止被系统回收。

```powershell
$TaskName = "WSL-AutoStart"
$DistroName = "Ubuntu" # 请替换为你的WSL发行版名称，可通过 `wsl -l -v` 查看
$Action = New-ScheduledTaskAction -Execute "wsl.exe" -Argument "-d $DistroName --exec sleep infinity"
$Trigger = New-ScheduledTaskTrigger -AtLogOn -User $env:USERNAME
$Settings = New-ScheduledTaskSettingsSet -AllowStartIfOnBatteries -DontStopIfGoingOnBatteries -StartWhenAvailable

Register-ScheduledTask -TaskName $TaskName -Action $Action -Trigger $Trigger -Settings $Settings -RunLevel Highest -Force
```

运行后，你可以立刻手动启动这个任务来测试一下效果：

```powershell
Start-ScheduledTask -TaskName "WSL-AutoStart"
```
如果之后想要移除这个自启动任务，可以执行：

```powershell
Unregister-ScheduledTask -TaskName "WSL-AutoStart" -Confirm:$false
```

💡 关键参数说明
- $DistroName：这是最重要的参数。脚本中默认是 "Ubuntu"，你需要将其替换为你实际使用的发行版名称。在PowerShell中运行 wsl -l -v 可以查看所有已安装的发行版及其准确名称。

- AtLogOn：触发器设置为“登录时”，意味着任务会在你登录Windows账户后启动。如果你希望系统开机即启动（无需用户登录），可以将其改为 -AtStartup，并确保在任务计划的“常规”设置中勾选“不管用户是否登录都要运行”。

- --exec sleep infinity：这个参数是保持WSL存活的关键。它会启动一个永不结束的 sleep 进程来“占位”，确保WSL实例不会因为没有任何前台任务而被Windows自动关闭。





## 🐧 方案二：让 WSL 内部的命令/服务自启

当WSL实例启动后，你可以通过配置让它自动执行初始化脚本或启动服务。

### 使用 wsl.conf 的 boot 设置
这是WSL原生的配置方式，在发行版内部修改 /etc/wsl.conf 文件。


1. 在WSL内创建启动脚本：例如 sudo nano /usr/local/bin/wsl-startup.sh，写入需要执行的命令，然后赋予执行权限 sudo chmod +x /usr/local/bin/wsl-startup.sh。

2. 编辑 wsl.conf：运行 sudo nano /etc/wsl.conf，添加以下内容：

```ini
[boot]
command = "/usr/local/bin/wsl-startup.sh"
```
boot.command 会在WSL实例启动时以 root 身份执行。

3. 使配置生效：在Windows PowerShell中运行 wsl --shutdown 完全关闭WSL，再次启动时脚本就会执行。注意，配置变更后需要等待约8秒让WSL完全停止，修改才会生效。

注意：boot.command 适合执行轻量的初始化任务，不适合长期运行的前台服务（如Web服务器），因为该命令的进程结束后可能会影响WSL实例的保活。

### 启用 systemd（管理后台服务的标准方式）
如果你的发行版使用 systemd，这是管理后台服务自启的最佳实践。

编辑 wsl.conf：在 /etc/wsl.conf 中添加：

```ini
[boot]
systemd=true
```

配置服务自启：执行 wsl --shutdown 使 systemd 生效。之后，WSL内的服务就可以像标准Linux一样，通过 sudo systemctl enable <服务名> 命令来设置为开机自启。

## 💡 补充：保持 WSL 持续运行（防回收）

一个常见的问题是：即使WSL启动了，当没有活动的终端会话时，Windows可能会自动“回收”WSL实例，导致后台服务中断。

解决方案是在启动WSL时，附加一个前台持久化进程来“占位”。最常用的命令就是在任务计划程序的操作参数中加入 -- sleep infinity，这会创建一个永不结束的 sleep 进程，从而保持WSL实例存活。

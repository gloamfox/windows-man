## 前言
为了充分利用wsl的性能，我们开发所依赖的软件建议都安装在wsl的虚拟机中，这里我们从头开始搭建一个java的开发环境

## JDK安装

```bash
# 安装jdk11
sudo apt install openjdk-11-jdk

# 搜索jdk名
apt search --names-only openjdk
```

安装后可以验证一下
```bash
java --version
```

## 安装Maven

```bash
sudo apt install maven
```

安装后验证一下
```bash
mvn --version
```
![alt text](<assets/09. java依赖环境安装/1792312306125.png>)

maven被安装到了`/usr/share/maven`这个路径下，需要注意的是他的配置被链接到了`/etc/maven`这个路径下

### 更改 maven 仓库源

在 WSL 终端中，用户级的配置文件路径通常是 ~/.m2/settings.xml。如果 .m2 目录或该文件不存在，可以手动创建。


```bash
mkdir -p ~/.m2
sudo cp /usr/share/maven/conf/settings.xml ~/.m2/settings.xml
nano ~/.m2/settings.xml
```

将以下 <mirror> 配置块添加到 settings.xml 的 <mirrors> 标签内。如果文件是新建的，需要包含完整的 <settings> 根标签。
```xml
<mirrors>
    <!-- 阿里云公共仓库镜像 -->
    <mirror>
        <id>aliyunmaven</id>
        <name>阿里云公共仓库</name>
        <url>https://maven.aliyun.com/repository/public</url>
        <mirrorOf>central</mirrorOf>
    </mirror>
</mirrors>
```

- url：https://maven.aliyun.com/repository/public 是阿里云推荐的公共仓库地址，它聚合了中央仓库和其他常用仓库，覆盖面广。
- mirrorOf：central 表示这个镜像专门用来替代 Maven 的中央仓库（Central Repository）。这是最常用且稳妥的设置，只拦截对中央仓库的请求。如果设置为 *，则会拦截所有仓库请求，包括你自己在 pom.xml 中定义的其他私有仓库，可能导致这些仓库失效，因此通常不推荐。

### 注意事项

使用 apt 安装 Maven 时最需要注意的一点：Ubuntu 官方软件源中提供的 Maven 版本通常不是最新的。

例如，在 Ubuntu 26.04.1 LTS 上，通过 apt 默认安装的可能就是 Maven 3.9.12，虽然这个版本“足够稳定”，但对于需要使用新特性或特定插件新版本的项目来说，可能会受限。

如果你的项目明确要求使用最新或指定版本的 Maven，建议放弃 apt，改为手动下载安装。这能让你获得对版本的完全控制权。

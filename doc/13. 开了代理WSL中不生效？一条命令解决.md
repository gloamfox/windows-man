用 WSL 开发的人，大概率都遇到过这个破事：Windows 上 Clash 一开，WSL 里的终端该连不上还是连不上，就算开启了网络镜像模式以及自动代理也非得 `wsl --shutdown` 重启一遍，代理才能够生效，一天折腾几回，心态真的会崩。

后来搞明白了，`autoProxy` 这东西只在 WSL 启动的那一瞬间读一次 Windows 的代理设置，它不是动态同步，就是个启动快照，只要 Clash 比 WSL 后启动，WSL 里就还是无代理状态。

那怎么办？思路很简单：自己写个后台小脚本，盯着 Clash 的端口，通了就把代理环境变量写到一个文件里，然后让 shell 自己去读。这样不管 Clash 什么时候开，WSL 这边都能跟上。

## 前提

**1. WSL 是否启用 systemd**

编辑 `/etc/wsl.conf`：
```ini
[boot]
systemd=true
```

改完在 PowerShell 里 `wsl --shutdown` 重启一次。

**2. Clash Verge 的 Allow LAN 是否打开**

设置 → Clash 设置 → 允许局域网连接，打开。

**3. Windows 防火墙放行端口**

以管理员身份开 PowerShell，把 Clash 的混合端口放行。比如你的混合端口是 7890：

```powershell
New-NetFirewallRule -DisplayName "WSL Clash Proxy" -Direction Inbound -Action Allow -Protocol TCP -LocalPort 7890
```


4.开启镜像模式

[WSL开启镜像模式](doc/03.%20WSL开发网络模式选择.md)

## 操作步骤

### 一键安装
```bash
bash <(curl -sL https://raw.githubusercontent.com/gloamfox/wsl-clash-proxy/main/install.sh)
```

自定义端口，如果clash的端口不是默认的7897，安装时可以自定义端口

```bash
PROXY_PORT=7897 bash <(curl -sL https://raw.githubusercontent.com/gloamfox/wsl-clash-proxy/main/install.sh)
```

### 卸载
```bash
bash <(curl -sL https://raw.githubusercontent.com/gloamfox/wsl-clash-proxy/main/uninstall.sh)
```

## 验证一下
新开个终端，先看变量：
```
echo $http_proxy
```

应该输出 `http://127.0.0.1:7890`。

再测连通性：

```bash
curl -s -o /dev/null -w '%{http_code}' https://www.google.com
```

这套东西的核心就一句话：**让一个后台进程持续盯着 Clash 的端口，把最新代理写进文件，shell 自己读。**

操作就这些，希望能帮你少重启几次 WSL。
